# 🔥 瓦斯行派工＋LINE 通知系統（Google Apps Script）

| 檔案 | 用途 |
|---|---|
| `Code.gs` | 後端：讀寫試算表、查客戶、建立訂單、呼叫 LINE Messaging API |
| `Index.html` | 前端：手機好用的「快速接單表單」 |

**流程：** 在表單輸入電話，老客戶自動帶出姓名、地址 → 選品項、時間、工人 → 按「送出並派工」→ 寫入 `Orders` → 用 LINE 推播給該工人（內含 Google 地圖導航連結）。

---

## 步驟一：建立試算表與程式

1. 到 [Google 試算表](https://sheets.new) 開一個新檔，命名為「瓦斯行派工系統」。
2. **檔案 > 設定 > 時區** 選「(GMT+08:00) 台北」。
3. 點選上方選單 **擴充功能 > Apps Script**。
4. 把預設的 `程式碼.gs` 內容全部刪掉，貼上 `Code.gs` 的內容。
5. 點左側「檔案」旁的 **＋ > HTML**，檔名輸入 `Index`（不用打 .html），貼上 `Index.html` 的內容。
6. 按 💾 儲存。
7. 回到試算表並**重新整理**，上方會出現 **🔥 瓦斯派工** 選單 → 點 **初始化工作表**。
   - 第一次會要求授權：選你的帳號 → 「進階」→「前往（不安全）」→「允許」。這是你自己寫的程式，可以放心。
8. 會自動建立 `Customers`、`Orders`、`Workers` 三個工作表。到 `Workers` 填入工人姓名（LINE User ID 先留空，步驟四再補）。

> 已經有舊的客戶名單？直接貼到 `Customers` 的 A（電話）、B（姓名）、C（地址）欄即可。電話就算在試算表中少了開頭的 0，系統也查得到。

## 步驟二：申請 LINE 官方帳號與 Messaging API

1. 到 [LINE Official Account Manager](https://manager.line.biz/) 用老闆的 LINE 登入，**建立 LINE 官方帳號**（名稱例如「XX瓦斯行派工」）。
2. 進入該帳號 → 右上 **設定** → 左側 **Messaging API** → **啟用 Messaging API**，選擇或建立一個 Provider（服務提供者）。
3. 同一個設定頁 → **回應設定**：
   - 「自動回應訊息」→ **關閉**（不然工人傳訊息會收到罐頭回覆）
   - 「Webhook」→ **開啟**
4. 到 [LINE Developers Console](https://developers.line.biz/console/) → 點剛才的 Provider → 點你的 Channel → **Messaging API** 分頁 → 最下方 **Channel access token (long-lived)** 按 **Issue**，複製這串很長的 token。
5. 回到 Apps Script → 左側齒輪 **專案設定** → 最下方 **指令碼屬性** → **新增指令碼屬性**：
   - 屬性：`LINE_CHANNEL_ACCESS_TOKEN`
   - 值：剛才複製的 token
   - 按「儲存指令碼屬性」。

> ⚠️ token 等同密碼，不要貼在程式碼裡或傳給別人。

## 步驟三：部署為網頁應用程式（接單表單）

1. Apps Script 右上 **部署 > 新增部署作業**。
2. 齒輪選 **網頁應用程式**，設定：
   - 說明：`接單表單`
   - 執行身分：**我**
   - 存取權：**只有我自己**（最安全，用你的 Google 帳號登入的手機／電腦才能開）
     - 若店裡其他人（例如老闆娘）也要用自己的帳號接單，改選「任何擁有 Google 帳戶的使用者」，但要注意**拿到網址的人都能下單**，網址別外流。
3. 按 **部署**，複製「網頁應用程式網址」（結尾是 `/exec`）。
4. 用手機瀏覽器打開該網址 → 「分享 > 加入主畫面」，以後就像 App 一樣一點就開。

> 🔁 **之後修改程式碼一定要重新發布**：**部署 > 管理部署作業 > ✏️ 編輯 > 版本選「新版本」> 部署**。否則網址還是跑舊程式（網址不變）。

## 步驟四：取得每位工人的 LINE User ID

LINE 推播需要的是 `U` 開頭、33 碼的 **User ID**（不是 LINE ID 帳號名稱）。程式已內建「工人傳訊息給官方帳號 → 自動回覆並記錄他的 User ID」的功能，但 LINE 需要一個公開網址才能把訊息送進來，所以要**暫時**多開一個部署：

1. **部署 > 新增部署作業 > 網頁應用程式**，說明填 `LINE webhook（暫時）`，執行身分「我」，存取權選 **任何人** → 部署 → 複製網址。
2. LINE Developers Console → Channel → **Messaging API** 分頁 → **Webhook URL** 貼上剛才的網址 → Update → 打開 **Use webhook**。
   - 按「Verify」可能顯示錯誤（302），**這是 Google 網址轉址造成的，正常現象**，實際訊息仍收得到，直接進行下一步測試即可。
3. 請每位工人用手機掃 Messaging API 分頁上的 **QR code** 加官方帳號好友，隨便傳一句話（例如「我是阿明」）。
4. 工人會收到回覆的 User ID，同時試算表會多一個 `LineUsers` 工作表記下「LINE 顯示名稱＋User ID」。
5. 把 User ID 複製到 `Workers` 工作表對應工人的 B 欄。
6. 全部人都設定好後，**回到 Apps Script > 部署 > 管理部署作業**，把「LINE webhook（暫時）」那個部署 **封存**，並在 LINE Developers 關閉 **Use webhook**。
   - 原因：這個部署是「任何人」都能開的，封存後接單表單就不會被外人看到。之後有新工人時再重複一次即可。

> 老闆自己的 User ID 可以直接在 LINE Developers Console → Channel → **Basic settings** 最下方的「Your user ID」找到，方便自己先測試。

## 步驟五：測試

1. 在試算表選單 **🔥 瓦斯派工 > 測試 LINE 推播**，Workers 第一位啟用的工人應收到測試訊息。
2. 打開接單表單，實際下一張單，確認：
   - `Orders` 多一列，最後一欄「LINE通知」顯示「已通知 MM/dd HH:mm」
   - 新客戶自動加入 `Customers`；再輸入同一支電話時會自動帶出資料
   - 工人收到的訊息格式如下：

```
🔥 新派工單 20261017-001
━━━━━━━━━━━━
👤 客戶：王先生
📞 電話：0912345678
📍 地址：台中市西區民生路100號
🛢️ 品項：20公斤 × 2（共 2 桶）
⏰ 時間：盡快送達
📝 備註：無
━━━━━━━━━━━━
🗺️ 導航：https://www.google.com/maps/search/?api=1&query=...
```

## 常見問題

| 狀況 | 處理方式 |
|---|---|
| 表單顯示「訂單已建立，但 LINE 通知失敗」 | 訂單已存好。看錯誤訊息修正（通常是 token 或 User ID 錯），然後在 `Orders` 點那一列 → 選單 **重送選取訂單的 LINE 通知**。 |
| 錯誤 `LINE API 400 ... to` | 該工人的 User ID 打錯，或對方還沒加官方帳號好友／已封鎖。 |
| 錯誤 `LINE API 401` | token 錯誤或過期，重新 Issue 並更新指令碼屬性。 |
| 錯誤 `LINE API 429` | 本月免費訊息額度用完（台灣免費方案每月約 200 則，以 LINE 官方公告為準），需升級方案。 |
| 改了程式但網頁沒變 | 沒有發布「新版本」，見步驟三最後的提醒。 |
| 想增減品項（例如加「50公斤」） | 修改 `Code.gs` 最上方 `CONFIG.ITEMS`，再發布新版本。 |
| 工人離職 | `Workers` 的「啟用」欄改為 `N`，表單就不會再出現他。 |
